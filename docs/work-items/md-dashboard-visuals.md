## Implementation contract

- Existing GET routes `/hris` and `/payroll` only; no new public API. New optional query parameters: `start` (strict ISO calendar date whose full 30-day window fits the supported date domain), `group` (`department` or `position`), `run_id` (positive integer) and `run_q` (valid UTF-8, at most 100 characters). Invalid date/group/search inputs receive visible fallback feedback. Invalid or foreign/unavailable run selections give generic unavailable feedback; they never fall back silently to another selected run.
- Tenant identity comes exclusively from the authenticated session. Prepared SELECT-only queries, same-tenant joins, literal LIKE wildcard escaping. No new branch/account selector or permission-policy change; preserve the prior organization-wide scope. Existing navigation flags control follow-up links. No financial values or employee names are newly queried for these charts.
- Each chart catches query failures separately. Missing tenant or model setup failure makes chart data unavailable; query failure is never converted into zero. Existing summaries remain independent. The inherited base Model still terminates on connection-construction failure; no global outage-handling rewrite was made.
- Shared server-rendered HTML, inline SVG and native GET forms/details; no new page JavaScript, chart dependency, CDN or build step. Static prerequisite messages do not query deferred financial or attendance data.
- Additive screen-only CSS scoped to new dashboard classes; white cards, Pearl & Teal tokens, semantic status colors, two columns at 1200px and above / one below, exact-value alternatives, visible keyboard focus, 44px control objective. Anchors use the existing dynamic navbar-height variable.
- Existing summaries, Needs Attention, recent runs, shortcuts and computation-state warnings remain intact. Destination links explicitly state dashboard filters are not applied on the existing page.
